# Research-to-Publication Workflow (v0.9 protocol)

This protocol defines how EEO moves from research questions to public publication while preserving evidence discipline, access governance, and safety boundaries.

## Lifecycle stages

| Stage | Purpose | Required inputs | Output | Failure condition |
|---|---|---|---|---|
| 1. Research question | Frame public-interest question | Scope, corridor context, doctrine | Research question statement | Question cannot be tied to public-interest purpose |
| 2. Source discovery | Identify candidate sources | Source inventory, licensing posture | Candidate source list | No authoritative source path |
| 3. Collection necessity review | Decide if collection is necessary | Access-governance criteria | Collect / aggregate / restrict / not collect decision | Collection exceeds necessity or violates do-no-harm |
| 4. Access-tier classification | Assign access posture | Object type, risk context | Access tier decision | Tier not assigned or rationale missing |
| 5. Authority/consent review | Validate authority and consent | Community/Indigenous or worker context | Authority/consent record or non-collection decision | No authority/consent where required |
| 6. Evidence classification | Classify evidence role/quality | Evidence links, source metadata | Evidence records with roles | Role/confidence undefined |
| 7. Analysis | Produce bounded interpretation | Evidence set, limitations | Draft analytical notes | Inference exceeds evidence limits |
| 8. Claim drafting | Draft public-safe claim text | Evidence, limitations, legal posture | Draft claim | No linked evidence or missing limitation text |
| 9. Source limitation review | Ensure limits are explicit | Sources, source map | Source limitation summary | Source constraints not disclosed |
| 10. Map-safety review | Assess spatial exposure risk | Spatial references, map classification | Map-safety decision | Spatial precision unsafe for context |
| 11. Right-of-reply review | Assess materially affected entities | Claim entity linkage | Right-of-reply status decision | Identifiable-actor claim without required response pathway |
| 12. Community/Indigenous review | Protect rights-bearing knowledge | Authority/consent basis | Community-safe publication posture | Rights-protected data exposed without governance basis |
| 13. Labor/human-rights review | Reduce harm to workers/community | Labor-risk data context | Human-rights-safe posture | Worker-identifying or retaliatory exposure risk unresolved |
| 14. Legal + language-safety review | Prevent adjudicatory overreach | Claim text, press language | Legal/language-safe approval | Overclaiming or legal-risk wording unresolved |
| 15. Release manifest update | Record publication state | Claim/evidence/governance status | Updated release manifest | Manifest not aligned with actual release state |
| 16. Publication | Publish approved material | Approved claim + manifest | Public release | Release gate incomplete |
| 17. Press handling | Communicate without overreach | Published dossier + manifest | Press summary with limitations | Press says more than public evidence supports |
| 18. Correction and revision | Enable public challenge and updates | Correction route + review workspace | Updated governance status and revision history | Correction pathway unavailable |
| 19. Incident response / emergency takedown | Contain harmful exposure quickly | Incident trigger + governance authority | Restriction/takedown + public update | Harmful material left public without action |
| 20. Retention/deletion review | Apply minimization and retention rules | Access decision + retention policy | Retain/aggregate/delete decision | Sensitive data kept without necessity |

## Hard stop publication failures

Do not publish if the claim lacks linked evidence, source limitations, access-tier decision, publication decision, map-safety review where relevant, and harm review where relevant.

Do not publish press materials if the release manifest has not been updated or if the press summary says more than the public evidence supports.
