# EEO Route Inventory and Launch Gate

## Purpose

This document maps the current EEO application routes to their intended public or internal function and defines launch gates before broader public sharing.

The goal is to keep implementation safe, incremental, evidence-disciplined, and loyal to the EEO doctrine.

EEO must remain a rights-aware, evidence-disciplined, federated public-interest observatory. It makes endowment-to-economy systems visible without claiming authority over peoples, states, territories, courts, communities, firms, or resources.

## MVP route principle

The public surface should explain and demonstrate the MVP loop:

source -> license -> evidence -> claim -> entity resolution -> review -> exposure review -> right-of-reply if needed -> release manifest -> public evidence dossier -> correction route

The MVP route set should support:

1. One flagship evidence dossier.
2. One limited corridor dashboard.
3. One evidence ledger.
4. One internal review workspace.
5. One right-of-reply and correction workflow.
6. One signed release manifest.
7. One safe corridor pilot.

These routes explain EEO’s identity, purpose, limits, methods, safeguards, correction pathway, and public posture.

- `/disclosure-policy`
- `/corrections`
- `/right-of-reply`

- `/privacy`
- `/accessibility`

Launch gate:

- No language implying EEO is a court, legal authority, global owner, registry, certifier, rating product, or redistribution engine.
- Must include correction or contact path where appropriate.
- Must clearly state limits of evidence and authority.
- Must avoid “prototype” language where it undermines public trust, except where describing demonstration-only data.

Launch gate:

- Every public claim must connect to evidence.
- Evidence must have source, source date or access date, license/use basis, method/context, confidence, limitation, and disclosure posture.
- Claims must show what they do not prove.
- Claims must show what would revise or correct them.
- Trade data must be treated as context, not chain-of-custody proof.
- Public revenue must be treated as a question, not proof of public benefit.
- Spatial proximity must not be treated as causation.
- Human dependency or capability information must remain aggregated, rights-aware, and non-exposing.

## Launch-blocking language

The following language should block public release if found in public-facing pages:

- “proof of illegality”
- “certified”
- “verified origin” from trade data alone
- “global resource ownership”
- “world resource registry”
- “resource redistribution engine”
- “company ranking”
- “country ranking”
- “ESG score”
- “AI determination”
- “blockchain trust layer”
- “public exposure engine”

## Required public disclaimers

Use variations of the following:

EEO documents available evidence, identifies uncertainty, and supports public-interest inquiry. It does not make legal findings, certify actors, verify product-level origin from trade data alone, adjudicate ownership, or assign liability.

Where demonstration data is used:

Some records may be synthetic or demonstration-only. No public data release is implied unless a signed release manifest is present.

For sensitive data:

Universal knowledge does not require universal exposure. EEO may aggregate, restrict, delay, or withhold information where publication could expose vulnerable communities, sacred sites, endangered ecological locations, whistleblowers, or other sensitive records.

## Route launch checklist

Before broad sharing, each public route should pass these checks:

- Page loads successfully.
- Navigation target exists.
- Page purpose is clear within 10 seconds.
- No outdated “prototype” language appears in primary public copy.
- No unsupported legal, ownership, certification, traceability, or causation claim appears.
- Evidence claims link to source/evidence context.
- Claims include limitations.
- Claims include correction or challenge pathway.
- Sensitive data is aggregated, restricted, or withheld.
- Page works on mobile.
- Page has accessible headings and link text.
- Footer disclaimer appears.
- Correction/right-of-reply path is findable.
