# EEO Implementation Roadmap

## Phase 0 — Doctrine and repository alignment

Goal: make the repository reflect the EEO doctrine before expanding product functionality.

Deliverables:

- cohesive foundational package saved;
- implementation index;
- endowment ontology;
- MVP scope guardrail;
- public language audit;
- route inventory.

Exit criteria:

- repository contains the canonical doctrine;
- public-facing language does not overclaim;
- no route implies EEO is a court, registry, certifier, ownership authority, or scoring system.

## Phase 1 — Public language and navigation refinement

Goal: make the public site clearer, safer, and more attractive without expanding claims.

Deliverables:

- homepage copy aligned with doctrine;
- navigation labels improved;
- metadata updated;
- disclaimer strengthened;
- “prototype” language softened where public-facing.

Exit criteria:

- homepage explains EEO in plain language;
- user understands the corridor, evidence ledger, methods, safeguards, and correction route;
- no public copy creates legal, certification, or ownership confusion.

## Phase 2 — MVP evidence operating system

Goal: make evidence traceable from source to public claim.

Deliverables:

- source registry structure;
- evidence record structure;
- claim record structure;
- confidence labels;
- disclosure tiers;
- review status;
- stale-after date;
- correction path.

Exit criteria:

- every public claim can point to source, method, confidence, disclosure tier, and correction route.

## Phase 3 — Corridor dossier and dashboard strengthening

Goal: improve the first corridor as a complete, limited, safe demonstration.

Deliverables:

- corridor overview;
- evidence dossier;
- value movement explanation;
- governance profile;
- labor/ecology/revenue context;
- limitations and non-claims;
- correction and right-of-reply link.

Exit criteria:

- one corridor tells a coherent endowment-to-economy story without overclaiming.

## Phase 4 — Internal review and release workflow

Goal: prevent unsafe publication.

Deliverables:

- internal review workspace;
- exposure review checklist;
- right-of-reply trigger rules;
- release manifest;
- correction log;
- maintenance process.

Exit criteria:

- no claim reaches public release without review status and publication decision.

## Phase 5 — Future expansion readiness

Goal: prepare for water, land, forests, biodiversity, energy, climate functions, and human dependency layers without premature public launch.

Deliverables:

- future ontology modules;
- data source map;
- partner criteria;
- disclosure rules;
- pilot selection framework.

Exit criteria:

- expansion is governed by evidence maturity, safety, and institutional readiness, not ambition alone.
