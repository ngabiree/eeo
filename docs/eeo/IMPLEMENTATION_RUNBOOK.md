# EEO Implementation Runbook

## Safe MVP Completion Target

EEO is complete enough for public beta when these exist together:

1. one safe corridor pilot;
2. one flagship evidence dossier;
3. one limited corridor dashboard;
4. one evidence ledger;
5. one internal review workspace;
6. one right-of-reply and correction workflow;
7. one signed release manifest;
8. one active maintenance framework.

## Canonical Evidence Loop

```text
source
→ license/use basis
→ evidence item
→ claim
→ entity resolution
→ evidence review
→ exposure review
→ right-of-reply if needed
→ release manifest
→ public dossier/dashboard
→ correction route
```

## Phase Sequence

### Phase 1: Foundation
- Freeze doctrine and MVP red lines.
- Add evidence schema, disclosure tiers, and safe language rules.
- Publish methodology and correction route pages using synthetic data only.

### Phase 2: Evidence Operations
- Build source registry.
- Build evidence ledger storage.
- Add entity-resolution review.
- Add internal review workspace.

### Phase 3: Pilot Corridor
- Select one commodity, geography, and chain using `docs/eeo/PILOT_CORRIDOR_SELECTION_FRAMEWORK.md`.
- Produce an internal selection memo before any real public claim is drafted.
- Ingest public or consent-cleared sources.
- Draft flagship dossier.
- Run exposure review.

### Phase 4: Public Beta
- Complete right-of-reply where triggered.
- Publish release manifest.
- Launch limited corridor dashboard.
- Activate correction workflow and maintenance schedule.

## Do Not Build Yet

- Global Endowment Atlas.
- Rankings or composite scores.
- Certification or seal.
- Public community reporting module.
- Exact sensitive geospatial downloads.
- Blockchain trust layer.
- AI chat as authority.
- Real-time alerting.
